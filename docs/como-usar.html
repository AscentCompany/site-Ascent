🚀 Ascent — Guia de Inicialização

Documentação do start.sh: como funciona, como rodar e como agendar com cron.

O que é o start.sh

O start.sh é o script de inicialização do projeto Ascent. Ele sobe todos os serviços do projeto em containers Docker conectados pela rede interna ascent, com o banco de dados MySQL persistindo os dados na pasta /dados/mysql.

O script é idempotente: pode ser executado várias vezes sem problema. Se um container já estiver rodando ele pula; se estiver parado ele reinicia.

Pré-requisitos

  • Docker instalado e rodando
  • Imagens publicadas no Docker Hub (lucasveneroso/ascent:*)
  • Arquivo .env na raiz do projeto (copie de .env.example)

Como usar manualmente

  1. Clone o projeto e entre na pasta raiz: 
    cd /caminho/para/site-Ascent
  2. Crie o arquivo .env a partir do exemplo: 
    cp .env.example .env
# Edite com suas credenciais reais
nano .env
  3. Dê permissão de execução (apenas na primeira vez): 
    chmod +x start.sh
  4. Execute o script: 
    bash start.sh

    O log de execução fica em /dados/logs/start.log.

Usando com cron

O cron é um agendador de tarefas do Linux. Ele permite executar o start.sh automaticamente — por exemplo, toda vez que o servidor reiniciar ou em intervalos fixos.

Abrir o editor de cron

crontab -e

Exemplos de agendamento

Adicione uma das linhas abaixo no final do arquivo:

Quando rodarLinha do cron
A cada 5 minutos */5 * * * * /caminho/para/site-Ascent/start.sh
Todo dia às 6h da manhã 0 6 * * * /caminho/para/site-Ascent/start.sh
Ao reiniciar o servidor @reboot /caminho/para/site-Ascent/start.sh
A cada hora 0 * * * * /caminho/para/site-Ascent/start.sh
⚠️ Atenção: No cron, o PATH do sistema é limitado. Use o caminho absoluto do script e garanta que o Docker esteja no PATH do cron. Se necessário, coloque o caminho completo do Docker: /usr/bin/docker.

Exemplo completo no cron (recomendado para servidor)

# Garante que o Docker esteja no PATH do cron
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin

# Sobe os containers ao reiniciar e a cada 5 minutos (se algum cair)
@reboot     /home/seu-usuario/site-Ascent/start.sh >> /dados/logs/cron.log 2>&1
*/5 * * * * /home/seu-usuario/site-Ascent/start.sh >> /dados/logs/cron.log 2>&1
💡 Dica: O >> /dados/logs/cron.log 2>&1 redireciona a saída do cron para um arquivo de log separado, útil para depuração.

Verificando os logs

# Log de execução do start.sh
tail -f /dados/logs/start.log

# Log gerado pelo cron (se configurado)
tail -f /dados/logs/cron.log

# Logs de um container específico
docker logs -f ascent-api
docker logs -f ascent-mysql
docker logs -f ascent-logs
docker logs -f ascent-apachepoi

Parar todos os containers

docker stop ascent-api ascent-logs ascent-apachepoi ascent-mysql
🗄️ Os dados do banco ficam em /dados/mysql. Parar os containers não apaga os dados. Eles só são perdidos se você remover manualmente essa pasta ou rodar docker rm -v ascent-mysql.
